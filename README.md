# dobutsu

どうぶつしょうぎの局面表現、合法手生成、終局判定、探索を提供する C++ ライブラリと、その上に載る CLI ツール。

このゲームは 2009 年に完全解析されている。
初期局面から到達可能な局面は 246,803,167 で、双方最善なら 78 手で後手が勝つ。
つまり、書いたエンジンが正しいかどうかを確かめる基準が最初から手元にある。
指し手生成が数え落としていないか、探索が本当に最善手を選んでいるか、いずれも既知の値と突き合わせて検証できる。

盤は 3 筋 4 段の 12 マス、駒は 5 種類、飛び利きの駒は存在しない。
このため occupancy に依存する利き計算が一切現れず、本将棋のエンジンで最も複雑になる部分が丸ごと消える。

```
   3   2   1
 +---+---+---+
 |きり|ライ|ぞう|  a  ← 後手
 +---+---+---+
 |   |ひよ|   |  b
 +---+---+---+
 |   |ヒヨ|   |  c
 +---+---+---+
 |ゾウ|ライ|キリ|  d  ← 先手
 +---+---+---+
```

## ビルド

CMake 3.20 以上と C++20 対応のコンパイラが要る。

```
cmake -S . -B build -G Ninja
cmake --build build
ctest --test-dir build --output-on-failure
```

初回の configure で GoogleTest を取得する。
オフラインで作業する場合は `-DDOBUTSU_BUILD_TESTS=OFF` を付ける。
詳細は [docs/BUILD.md](docs/BUILD.md) にある。

## 構成

```
include/dobutsu/   公開ヘッダ。コアの実体はここに置く
src/               ヘッダに置けない実装
cli/               CLI エントリポイント
tests/             GoogleTest によるテスト
docs/              仕様、ロードマップ、設計判断
```

コアライブラリは標準ライブラリ以外に依存しない。
外部への依存はテストフレームワークとビルドツールだけに閉じている。

局面と指し手は小さく詰める。
指し手は 16 ビット、局面は 64 バイト以内に収め、利きテーブルは 288 バイトで L1 キャッシュに常駐させる。
設計の参照先は cshogi であり、そこで確立している「ヘッダ中心の高速コアと薄い外部インタフェース」という構造を、どうぶつしょうぎの規模に合わせて再構成している。
